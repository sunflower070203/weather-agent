## 天气 API 约定（2026-08-04 核验）

当前选用“全球范围10天基础要素包（60分钟间隔）”：

- 请求方式：`GET https://api.tjweather.com/v2`；
- 查询范围：全球单点经纬度；
- 时间分辨率：1小时；
- 预报时效：最长10天；
- 更新频率：每日2次；
- 返回格式：JSON；
- 试用额度：1000次，QPS 5次/秒；
- 有效期：2026-08-03 至 2026-09-02；
- 鉴权参数：`key` 与 `subscriptionId`；
- 密钥环境变量：`TJWEATHER_API_KEY`；
- 订阅标识环境变量：`TJWEATHER_SUBSCRIPTION_ID`。

支持要素：

| 编码 | 含义 | 单位 | MVP用途 |
|---|---|---|---|
| `wd10m` | 10米风向 | ° | 风向说明 |
| `ws10m` | 10米风速 | m/s | 大风风险 |
| `t2m` | 2米温度 | °C | 高温、低温风险 |
| `rh2m` | 2米相对湿度 | % | 体感和辅助说明 |
| `psz` | 地表气压 | Pa | 保留，不直接作为首版风险规则 |
| `tp` | 降水 | mm/hr | 降雨风险 |

默认请求字段为 `wd10m,ws10m,t2m,rh2m,psz,tp`。接口返回 `code`、`message` 和 `data`；`data` 中包含单位、逐时要素数据及起报时间。

已实测时间分辨率参数：`t_res=1h` 返回业务码 `200`、240个逐小时数据点，相邻时间间隔60分钟；`t_res=60min` 返回 HTTP 403。项目统一使用 `1h`，不得照抄官网 Python 示例中的 `60min`。

## 变更规则

1. 它是否直接增强核心决策闭环？

3. 是否有独立的验收方法？
4. 是否会威胁 2026-08-09 的内部截止日期？

### 2026-08-04 / 天机天气 API 接入验证

- 本阶段目标：确认凭证、接口参数、响应结构和正确时间分辨率；
- 实际完成：建立最小天气客户端及4项单元测试，完成真实 API 脱敏调用；
- 验证方式与结果：`1h` 返回业务码200、240个数据点、60分钟时间步长；`60min` 返回 HTTP 403；
- 发现的问题：当前 MSYS2 Python 缺少可用 CA 证书，Windows PowerShell TLS 请求正常，属于本地临时运行时问题；
- 做出的关键决策：统一使用 `t_res=1h`，不关闭 TLS 验证，不记录密钥或完整请求 URL；

- 发现的问题：复杂相对时间和“一晚、半天”等开放式表达仍取决于远端模型，单元测试只能验证提示上下文、字段白名单和返回值校验；Gradio 构建测试在 Windows 会输出未关闭事件循环的 `ResourceWarning`，不影响测试结果；

固定20项对抗矩阵：

1. 信息不足时只追问下一字段且不调用工具；
2. 多地点候选必须由用户确认；
3. 纯数字地点选择；
4. “第二个”等中文序数词选择；
5. “选北京那个”等唯一名称片段选择；
6. 0、越界数字和无效序数不改变候选状态；
7. “都不是”只清除地点；
8. 候选状态下改写地点会重新进入提取与查询；
9. 仅标点输入不调用模型；
10. 对话内“重新开始”清除计划和候选；
11. 地理编码失败保留计划并提示重试；
12. 天气服务失败不生成适宜性结论；
13. 活动时间超出预报范围时建议调整时间；
14. 城市级近似坐标必须明确标注；
15. 无风险建议显示公开决策依据；
16. 有风险建议显示命中的规则、等级、数值和单位；
17. 模型非 JSON 对象返回被拒绝且旧计划不变；
18. 非法活动类型被领域校验拒绝；
19. 提示注入产生的越权字段被白名单丢弃；
20. 模型解析失败在 UI 中保留计划摘要并提示换一种说法。
