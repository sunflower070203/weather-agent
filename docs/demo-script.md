# 三分钟演示脚本（专家技能版）

演示目标是证明 Agent 的决策闭环与三位专家分工。录制前先确认页面底部版本与提交候选版一致（当前候选：`rc-d7c4990`）。

## 0:00—0:25 问题与边界

打开公开创空间，说明普通天气查询只能返回数据，本项目处理的是“某次户外活动该怎么安排”。当前支持骑行、徒步和露营；回复由三位确定性专家分工输出——气象顾问解读时段天气、户外安全顾问给结论与方案、装备与补给顾问给装备建议。使用城市级坐标近似，不代替官方天气预警。

## 0:25—1:10 不完整输入与主动补全

在新会话输入“周六想在北京骑行。”按照页面追问补充开始时间和时长；如出现地点候选，选择合理候选。指出右侧计划摘要会保留结构化活动状态。

## 1:10—2:00 三位专家与可解释决策

等待评估完成，指出回复按三段输出：

- **气象顾问**：时段概况、通俗解读与决策依据（地点、时段、预报起报时间、规则结果、风险峰值）；
- **户外安全顾问**：风险结论、方案一/方案二（有风险时给出替代时段或缓解动作）与偏好提示；
- **装备与补给顾问**：按活动与风险给出装备建议，每条带知识库来源。

说明天气来自天机天气 API，风险等级由程序规则计算；语言模型负责理解输入，不能补写天气数值；建议可追溯到规则与知识库条目。

## 2:00—2:30 修改计划并重评估

在同一会话输入“改到下午两点，其他不变。”展示活动类型、地点和时长仍被保留，开始时间发生变化，Agent 重新查询并输出新的三段结论。这是多轮状态与闭环重规划的核心证据。

## 2:30—2:50 安全边界

点击“重新开始”，输入“昨天在北京骑行 1000 小时。”展示系统拒绝过去时间或非法时长，不生成伪造天气结论。如果线上响应与预期不符，停止录制并回到发布检查清单。

## 2:50—3:00 收尾

回到页面底部显示运行版本，用一句话总结：项目完成了“理解计划—调用工具—三位专家分工决策—修改后重评估—异常时安全停止”的最小 Agent 闭环。
