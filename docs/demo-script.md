# 三分钟演示脚本

演示目标是证明 Agent 的决策闭环。录制前先确认页面底部版本与提交候选版一致。

## 0:00—0:25 问题与边界

打开公开创空间，说明普通天气查询只能返回数据，本项目处理的是“某次户外活动该怎么安排”。当前支持骑行、徒步和露营，使用城市级坐标近似，不代替官方天气预警。

## 0:25—1:15 不完整输入与主动补全

在新会话输入“周六想在北京骑行。”按照页面追问补充开始时间和时长；如出现地点候选，选择合理候选。指出右侧计划摘要会保留结构化活动状态。

## 1:15—2:05 工具调用与可解释决策

等待评估完成，展示查询地点和时段、天气数值与单位、命中的风险规则、主方案和备选方案。说明天气来自天机天气 API，风险等级由程序规则计算；语言模型负责理解输入和组织解释，不能补写天气数值。

## 2:05—2:35 修改计划并重评估

在同一会话输入“改到下午两点，其他不变。”展示活动类型、地点和时长仍被保留，开始时间发生变化，Agent 重新查询并输出新结论。这是多轮状态与闭环重规划的核心证据。

## 2:35—2:55 安全边界

点击“重新开始”，输入“昨天在北京骑行 1000 小时。”展示系统拒绝过去时间或非法时长，不生成伪造天气结论。如果线上响应与预期不符，停止录制并回到发布检查清单。

## 2:55—3:00 收尾

回到页面底部显示运行版本，用一句话总结：项目完成了“理解计划—调用工具—规则决策—修改后重评估—异常时安全停止”的最小 Agent 闭环。
