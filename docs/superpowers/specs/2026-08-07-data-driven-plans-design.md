# 数据化方案设计

## 目标

方案一/方案二不再使用固定模板，而是基于逐小时预报数据给出具体建议，解决“回复空洞”的问题，同时保持完全确定性、可测试。

## 算法

### 替代时段搜索（`planning.find_clear_window`）

- 窗口长度 = `ceil(时长)`，三小时活动覆盖三个逐小时点；
- 候选窗口内 `assess_weather_risks` 不含 medium/high 风险即视为“无风险”；
- 搜索范围 = 原开始时间 ± 48 小时；
- 多个候选时取距离原开始时间最近的窗口，平局取更早；
- 找不到时返回 `None`，Agent 降级为原模板文案。

### 风险峰值（`planning.peak_risks`）

- 每个风险类型取等级最高的一条，输出数值、单位与发生时刻，作为“决策依据”的补充证据。

## 消息格式

有风险且找到替代时段：

```text
1. 方案一：建议将活动调整到 08月08日 11:00 至 14:00，该时段未命中降雨风险。
2. 方案二：携带雨具并避开积水路段，并缩短暴露时间；若风险持续则取消活动。
```

有风险但找不到替代时段：

```text
1. 方案一：调整活动时间，避开风险较高的时段后重新查询。
2. 方案二：携带雨具并避开积水路段，并缩短暴露时间；若风险持续则取消活动。
```

决策依据新增“风险峰值”行，例如：

```text
- 风险峰值：precipitation high 8.0 mm/hr（08:00）
```

## 评测

- 单测：最近无风险窗口、全风险返回 None、非整数时长向上取整、风险峰值按类型取最高；
- Agent 测试：有替代时段时给出具体时段；无替代时段时保留降级文案并展示峰值；
- 评测场景 `agent.026`（数据化替代时段）、`agent.027`（风险峰值降级）。

## 局限

- 按整小时粒度近似，替代时段的起止为整点；
- 候选完全取决于预报覆盖的数据点，点太少时不会给出时段建议；
- 搜索半径固定 48 小时，超出范围不推荐。
