# 比赛提交版冻结设计

## 目标

在 2026 年 8 月 9 日结束前形成一个可运行、可演示、可复现、可追溯的提交候选版本。8 月 10 日以后只允许处理提交表单、部署故障和阻断演示的问题，不再扩展产品能力。

## 已确认事实

- 基线为 GitHub `origin/main` 的 merge commit `8c10dff`。
- 基线的 57 项自动化测试全部通过。
- 代码已经在地理编码前校验过去时间和超过 168 小时的时长，并已有相应测试。
- ModelScope 线上黑盒测试仍出现旧行为：北京没有确定性命中、过去时间先进入地点候选、1000 小时被接受。
- 因此当前首要问题不是继续重复实现校验，而是证明线上运行的代码版本，并重新完成部署验收。

## 范围

### 必须完成

1. **版本可追溯**
   - 页面展示短版本号，使评审者和开发者能够确认线上实际运行版本。
   - 版本号优先读取部署环境变量；未配置时使用提交版的静态版本标识。
   - 版本标识不得包含密钥、完整环境信息或用户信息。

2. **提交材料**
   - 修正 README 中已经过期的进度、测试数量和下一阶段说明。
   - 新增一份提交清单，覆盖作品链接、环境变量、部署步骤、验收步骤和最终提交凭证。
   - 新增一份三分钟演示脚本，固定主流程、修改计划流程和安全拒绝流程。
   - 新增一份架构与 Agent 性说明，解释状态、工具、决策和反馈闭环，避免作品被误解为普通 chatbot。
   - 新增一份开发复盘，记录需求收缩、状态机、真实工具、测试、部署和已知限制。

3. **提交版验收**
   - 本地完整运行 57 项以上自动化测试和 Python 编译检查。
   - 部署后页面短版本号必须与候选版本一致。
   - 线上依次验证：完整计划得到建议、修改计划触发重新评估、过去时间被拒绝、1000 小时被拒绝、重置后旧状态消失。
   - 任一安全拒绝失败，提交版不得标记为验收通过。

4. **可恢复交付物**
   - GitHub 保留提交候选分支和可审查 PR。
   - ModelScope 使用普通提交保留平台历史，不强推。
   - 验收通过后创建明确的提交候选 tag，并生成不含 `.git`、密钥、本地虚拟环境和工作区文件的源码压缩包。

### 明确不做

- Skill、RAG、长期 Memory、多 Agent 或新的 Agent 框架。
- 新增第三方模型或天气数据源。
- UI 重设计、账号系统、数据库、分析埋点。
- 为非阻断问题进行大范围重构。
- 为追求“产品丰富度”新增活动类型。

## 结构设计

### 版本标识

版本信息保持为 UI 薄层能力，不进入 `WeatherAgent` 决策内核。`weather_agent/ui.py` 负责读取安全的版本字符串并在页脚附近展示。测试只验证展示值和默认值，不依赖 Git 命令或网络。

### 文档包

- `README.md`：作品入口、真实能力、运行方法、当前验证状态和已知限制。
- `docs/submission-checklist.md`：提交前逐项核对表。
- `docs/demo-script.md`：三分钟演示操作与讲解。
- `docs/architecture.md`：单 Agent 状态机、工具调用和决策数据流。
- `docs/development-retrospective.md`：可复用的 Agent 开发流程复盘。

文档只描述已经实现且能够验证的行为。不得把规划中的 Skill、RAG、Memory 或多 Agent 写成当前能力。

## 数据流与安全边界

用户输入先由提取器更新 `ActivityPlan`，确定性状态机负责缺失字段追问、边界校验和地点候选状态，随后才允许调用地理编码和天气工具。天气数据经过规则评估后生成两套行动方案。外部工具失败时必须停止可信判断并给出重试建议。

密钥只通过 ModelScope 密文或本地环境变量注入。文档、截图、日志、压缩包和版本信息均不得包含实际密钥或带访问令牌的 URL。

## 验收标准

- 自动化测试全部通过且无失败。
- `compileall` 成功。
- Git diff 不包含密钥、访问令牌、虚拟环境或无关格式化。
- README 与提交材料中的测试数量、版本和已知限制一致。
- ModelScope 页面显示与候选版本一致的短版本号。
- 五条线上回归全部得到确定性结果，其中过去时间和 1000 小时不得调用地点或天气工具形成建议。
- 源码压缩包可以在仅配置三个必需环境变量后启动。

## 失败处理

- 若本地测试失败：停止打包，先定位回归来源。
- 若线上版本号不一致：不修改业务逻辑，先重新部署并检查平台运行日志。
- 若版本一致但线上行为仍不同：记录真实模型输出与状态更新，补最小回归测试后修复。
- 若 ModelScope 在提交窗口发生故障：保留 GitHub commit、tag、源码包、测试输出和演示录屏作为恢复证据。

## 后续优先级

提交候选版本完成后，下一项只建设一个“天气活动安全 Skill”，把现有计划补全、天气工具和风险规则封装为可复用能力。Skill 验证稳定后再评估短期会话 Memory；RAG 和多 Agent 都不是当前问题的必要解法。
