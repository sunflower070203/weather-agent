# Agent 架构与能力边界

## 核心闭环

```text
用户输入 -> 结构化提取与字段白名单 -> ActivityPlan 会话状态
-> 缺失信息追问或地点确认 -> 天气工具 -> 活动时段筛选
-> 确定性风险规则 -> 知识建议检索 -> 主方案与备选方案 -> 修改计划后再次执行
```

语言模型处理口语表达和字段提取；参数校验、天气请求、时间筛选、风险计算、状态变更和错误分类由 Python 程序负责。模型输出先经过类型与字段白名单校验，不能直接成为可信天气事实。

## 为什么它属于 Agent

Agent 的判定标准包括持续目标、可观察状态、外部行动、结果校验和反馈循环。聊天界面本身不能证明这些能力。本项目保存 `ActivityPlan`，在信息不足时主动补全，通过工具获取外部天气事实，使用规则形成决策，并在计划变化后重新行动。工具失败或输入越界时，系统停止结论生成。

它仍是范围受控的单 Agent。工具选择和流程大部分由显式状态机约束，开放性低于通用自主 Agent。把它称为“完全自主 Agent”并不准确。

## 主要模块

| 模块 | 职责 | 可信边界 |
|---|---|---|
| `activity.py` | 活动计划领域对象 | 拒绝非法活动类型和字段 |
| `modelscope.py` | 调用 Qwen 提取计划更新 | 返回值需本地校验并归一化偏好 |
| `geocoding.py` | 地名查询与候选确认 | 具体地点可能降级为城市级近似 |
| `weather.py` | 获取并解析逐小时数据 | 失败时不得生成适宜性结论 |
| `risk.py` | 计算四类风险 | 产品阈值，不是官方预警 |
| `knowledge.py` | 活动建议检索与来源标注 | 确定性主题匹配，不替代官方预警 |
| `planning.py` | 替代时段搜索与风险峰值 | 确定性扫描，复用风险规则阈值 |
| `agent.py` | 状态机、编排、偏好口径、重评估与降级 | 单会话状态，无跨会话记忆 |
| `ui.py` | Gradio 界面与版本标识 | 展示层不负责风险判断 |

## 数据、部署与限制

密钥通过 `MODELSCOPE_ACCESS_TOKEN`、`TJWEATHER_API_KEY` 和 `TJWEATHER_SUBSCRIPTION_ID` 注入。`WEATHER_AGENT_VERSION` 只标记发布版本。每个浏览器会话创建独立状态；项目没有账号、数据库或跨会话记忆。

- 地理编码面向城市更可靠，公园或路线可能使用城市级坐标近似。
- 超出天气服务预报时效的日期会被拒绝。
- 风险规则仅覆盖降雨、大风、高温和低温，不替代官方预警、路线安全评估或医疗建议。
- 已提供小型确定性知识库（按活动与风险主题检索并标注来源）与会话内偏好记忆；未引入向量 RAG、MCP、跨会话长期记忆和多 Agent，演进设计见 `docs/superpowers/specs/2026-08-07-knowledge-skill-design.md` 与 `docs/superpowers/specs/2026-08-07-preference-memory-design.md`。
